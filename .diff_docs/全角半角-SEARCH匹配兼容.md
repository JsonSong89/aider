# 全角 / 半角 SEARCH 匹配兼容

### 背景

中文用户在使用 SEARCH/REPLACE（`edit_format=diff`）时，经常遇到这类失败：

- 源文件中文注释使用全角标点（如 `，` `。`）
- 模型返回的 SEARCH 块写成半角（如 `,` `.`），或反过来

原有匹配逻辑要求 SEARCH 与文件内容**逐字符精确相等**（仅额外容忍缩进 / 首行空行 / `...` 省略），因此全角半角不一致会直接导致：

`SearchReplaceNoExactMatch: This SEARCH block failed to exactly match lines`

### 改动位置

`aider/coders/editblock_coder.py` → `replace_most_similar_chunk`

在精确匹配、空白容错、`...` 省略处理都失败后，新增一步兜底：

`replace_with_cjk_punct_flexibility`

### 行为说明

| 项目 | 策略 |
|---|---|
| SEARCH | 仅对窄范围标点做归一化后再比较 |
| REPLACE | **跟随 AI 输出**，不做全角/半角改写 |
| 多处命中 | 拒绝应用（要求归一化后唯一匹配） |

### 归一化范围（收窄）

仅处理以下全角 → 半角（比较用）：

| 全角 | 半角 |
|---|---|
| `，` | `,` |
| `。` | `.` |
| `；` | `;` |
| `：` | `:` |
| `？` | `?` |
| `！` | `!` |
| `（` `）` | `(` `)` |
| `【` `】` | `[` `]` |

其他全角符号（如 `「」`、全角字母数字等）**不做处理**，以降低误匹配风险。也不使用完整 `NFKC` 归一化。

### 示例

文件中：

```python
# 计算阶乘，并返回结果。
def factorial(n):
    ...
```

模型 SEARCH（半角标点）：

```text
# 计算阶乘,并返回结果.
def factorial(n):
```

原先：匹配失败。  
现在：SEARCH 归一化后可唯一命中，REPLACE 按模型原文写入。

### 风险与边界

- 只影响「精确匹配已失败」的路径，成功路径行为不变。
- 不改写磁盘上未匹配到的原文标点风格。
- 若归一化后 SEARCH 对应多处，宁可不改，避免误伤。
- 若 SEARCH 与 REPLACE 公共上下文的标点风格不一致，写入后可能带入模型侧标点；这是块替换机制本身的问题，缩小编辑块可缓解。
